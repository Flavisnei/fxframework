Instalar e ativar

Requisitos: PHP 8.1+, PDO SQLite, Composer, requisitos transitivos do Admin e uma cópia deste repositório. O exemplo usa os pacotes locais por path; não é um pacote publicado para download remoto. Execute em examples/contacts:

composer install
php vendor/bin/fxartisan admin:init --email=seu-email@example.com
php vendor/bin/fxartisan contacts:init
php vendor/bin/fxartisan module:enable contacts
php -S 127.0.0.1:8080 -t public public/index.php

O comando solicita uma senha; não existe senha padrão. A ativação inclui fx-admin como dependência. Abra http://127.0.0.1:8080/admin, entre e escolha Contatos. O resultado inicial é uma lista vazia. contacts:init pode ser repetido sem apagar registros. Não o execute como migração de versões futuras: ele só cria o esquema inicial.

Os bancos ficam em storage/admin.sqlite e storage/contacts.sqlite, fora de public. Em HTTPS configure secure_cookie=true. O exemplo é separado de examples/admin e não usa suas contas ou configuração SMTP. Para desativar: php vendor/bin/fxartisan module:disable contacts. Isso remove telas e APIs no próximo bootstrap, preservando o banco. Reative pelo mesmo comando de ativação.

Cadastrar, localizar e editar

  1. Escolha Novo contato. Informe nome (2–120 bytes) e email válido e único (até 254 bytes). Telefone (40 bytes) e observações (2000 bytes) são opcionais.
  2. Salve. Em caso de erro, o campo é identificado e o formulário preserva seu texto. Caracteres acentuados podem ocupar mais de um byte.
  3. Busque por parte do nome ou email e use Anterior/Próxima. Cada página contém até 20 contatos; observações só são carregadas ao abrir o registro.
  4. Use Editar, ou Ver se tiver somente leitura. Para excluir, confirme o contato escolhido; a exclusão é definitiva.

Resultado esperado: uma alteração aparece após nova consulta sem recarregar o painel. Dados são exibidos como texto, inclusive caracteres HTML. A busca trata % e _ literalmente; correspondência de maiúsculas/acentos segue o LIKE do SQLite, sem normalização linguística adicional.

Controlar acesso

config/admin.php declara contacts.view, contacts.create, contacts.update e contacts.delete. O perfil Administrador reservado tem todas as permissões configuradas. Outros perfis precisam receber explicitamente dashboard.view e contacts.view, mais as operações desejadas. Na janela Perfis, marque apenas o necessário e atribua o perfil ao usuário.

Ocultar botões não é autorização: o servidor verifica cada operação. Não existe isolamento por proprietário ou empresa: quem pode consultar vê todos os contatos deste banco. O manifesto lista metadados; as permissões adicionais são habilitadas explicitamente na configuração da aplicação.

Usar a API JSON

Base: /admin/api. Sessão por cookie do painel; obtenha csrf em GET /admin/api/session e envie X-CSRF-TOKEN nas operações POST, PUT e DELETE. Não coloque o token na URL. Corpos limitados a 16 KiB.

GET    /admin/api/contacts?page=1&q=Ana
POST   /admin/api/contacts/read   {"id":1}
POST   /admin/api/contacts        {"name":"Ana Silva","email":"ana@example.test"}
PUT    /admin/api/contacts        {"id":1,"version":1,"name":"Ana Souza","email":"ana@example.test","phone":"","notes":""}
DELETE /admin/api/contacts        {"id":1,"version":2}

A leitura de detalhe usa POST para manter o identificador no corpo e exige CSRF. Criação/edição retornam registro completo com id e version; sucesso usa HTTP 200. PUT substitui os campos editáveis, portanto telefone e observações omitidos ficam vazios. Listagem retorna data, page, per_page e total.

{"message":"Revise os campos indicados.","errors":{"email":"Informe um email valido."}}

422 indica entrada inválida; 409, email duplicado ou versão desatualizada; 404, contato ausente; 401, sessão encerrada; 403, permissão/CSRF. O contador version aumenta a cada edição: um formulário antigo não pode sobrescrever ou excluir uma edição mais recente.

Problemas comuns e dicas

Contatos não aparece: confira module:status, module:doctor, configuração das permissões e perfil do usuário. Execute contacts:init antes de ativar o módulo. Atualize o painel após ativar ou desativar.

Conflito de versão: copie o texto que deseja preservar, feche e reabra o cadastro e compare a alteração atual antes de salvar. Não substitua automaticamente a versão enviada.

Falha de rede ao salvar: consulte a lista antes de repetir, pois a operação pode ter sido concluída. A tela não repete gravações automaticamente. Email é único; confira o registro existente.

Sessão/CSRF: entre novamente no painel e reabra Contatos. O formulário preserva seus valores quando recebe erro. Faça backup dos dois bancos e do estado dos módulos; não versione dados reais.

Escopo e próximos passos

Exemplo funcional com SQLite, sem dependências novas no Core. Não há importação, anexos, lixeira, auditoria das alterações de contatos, multiempresa ou pesquisa especializada. Revisão visual no navegador e benchmarks continuam pendentes; testes HTTP não comprovam renderização nem escala.

Para verificar sem dados reais: na raiz execute php vendor/bin/phpunit --do-not-cache-result e, após instalar este exemplo, php tests/integration/contacts.php. Os testes usam bancos temporários.
