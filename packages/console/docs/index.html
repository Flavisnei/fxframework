Catálogos de instalação locais e remotos

Objetivo: escolher componentes e presets de um catálogo JSON da sua organização, além do catálogo embutido do FX Artisan. Requer FX Console atualizado, Composer 2 e um projeto com composer.json. Leitura HTTPS requer OpenSSL, allow_url_fopen habilitado e certificados confiáveis no PHP CLI.

Compatibilidade

Sem opções novas, module:list, module:install e preset:install mantêm o catálogo e comportamento anteriores. --catalog seleciona outro catálogo apenas para a execução atual; ele substitui a seleção embutida, sem mesclar nem persistir configuração. A API ComposerInstaller::install aceita um último argumento opcional InstallCatalog; chamadas existentes continuam válidas.

Passos e exemplo

No checkout completo, liste o catálogo distribuído (em instalação independente, use vendor/bin/fxartisan e um catálogo próprio):

php bin/fxartisan module:list --catalog=docs/catalog.json

Para conferir o mesmo catálogo por HTTPS:

php bin/fxartisan module:list --catalog=https://raw.githubusercontent.com/Flavisnei/fxframework/097b04de98f46eef027199194515fcd2d933be4a/docs/catalog.json --catalog-sha256=3b1bc06b5dc11bc92b1f5811a8fac0254f6fc6cb7e34b405c480de3cf27ae7c3

O SHA-256 confere os bytes recebidos; obtenha o valor de uma revisão confiável. A URL do exemplo já está fixada na revisão testada; mantenha uma revisão explícita para reprodução duradoura. HTTPS exige hash explícito; o hash não substitui avaliação do fornecedor ou do código dos pacotes.

Na aplicação consumidora, use o mesmo catálogo e hash para simular a instalação. Exemplo com catálogo local previamente revisado e pacotes FX configurados por repositório Composer path:

vendor/bin/fxartisan preset:install minimal --catalog=catalogo.json --constraint=@dev --dry-run
vendor/bin/fxartisan preset:install minimal --catalog=catalogo.json --constraint=@dev

Resultado esperado: Composer resolve o pacote selecionado e suas dependências; a segunda execução instala. Scripts e plugins ficam desabilitados. Providers, permissões, migrations e ativação permanecem explícitos. Catálogo não adiciona repositórios ao composer.json e não hospeda pacotes: configure fontes confiáveis no consumidor. Os pacotes FX continuam disponíveis no checkout por path, sem publicação no Packagist.

Verificado: catálogo HTTPS lido com SHA-256 e preset mínimo instalado em consumidor temporário, com Core isolado. A CI do commit 097b04d passou nas oito tarefas, incluindo o teste de catálogo com Composer real.

Formato para catálogos próprios

{
  "schema": 1,
  "components": {
    "crm": {"package": "suaempresa/crm", "description": "Cadastro comercial"}
  },
  "presets": {"comercial": ["crm"]}
}

O exemplo suaempresa/crm é ilustrativo. Use nomes reais publicados no repositório Composer da sua organização. Aliases usam letras minúsculas, números e hífen; nomes de pacotes usam fornecedor/pacote. Presets referenciam aliases existentes, sem repetições. Somente os campos exibidos são aceitos; não inclua comandos, repositórios, credenciais ou código PHP.

Problemas comuns e dicas

Hash divergente: nenhum pacote é solicitado ao Composer; revise a mudança antes de atualizar o hash. Falha HTTPS: confira certificados e rede, sem desabilitar TLS. HTTP simples e redirecionamentos são recusados. Pacote não encontrado: configure o repositório Composer; o catálogo não publica nem baixa arquivos por conta própria. Limites: até 256 KiB, 200 componentes, 50 presets e tempo de leitura de 15 segundos. Guarde uma cópia local revisada para consultar o catálogo offline; instalar dependências pode exigir rede ou cache do Composer.

Verificação reproduzível: após instalar o vendor de examples/console, execute php tests/integration/catalog.php C:/composer/composer.phar na raiz (ajuste o caminho ao seu ambiente). O teste cria um pacote sintético e consumidor temporários, confere simulação, instalação real, autoload isolado e rejeição de adulteração, sem tocar nos seus projetos. Publicação de pacotes independentes e teste de capacidade HTTP permanecem etapas separadas.

Instalação local

FX Core e Symfony Console. Não instala HTTP, banco, Smarty ou FX Windows.

Requisitos: PHP ^8.1 e Composer 2. Em uma aplicação irmã de fxframework, use este composer.json e execute composer install. O wildcard permite resolver os pacotes FX dependentes.

{
  "name": "fx/exemplo",
  "repositories": [
    {
      "type": "path",
      "url": "../fxframework/packages/*"
    }
  ],
  "require": {
    "fxfavalessa/fx-console": "@dev"
  },
  "minimum-stability": "dev",
  "prefer-stable": true
}

Pacotes em desenvolvimento local, ainda não publicados. minimum-stability dev é necessário para os pacotes FX transitivos; prefer-stable prioriza versões estáveis externas. Não publique esses comandos como instalação de release estável.

Exemplo

Para PHP, carregue vendor/autoload.php da aplicação antes do exemplo.

php vendor/bin/fxartisan list
php vendor/bin/fxartisan about
php vendor/bin/fxartisan make:controller Exemplo

Exibe os comandos disponíveis e gera uma classe de controller na aplicação.

Pacotes e presets

Instalar conforme a necessidade

Requisitos: PHP ^8.1, Composer 2 e um projeto com composer.json. Execute os comandos na raiz desse projeto. O catálogo é fechado aos onze componentes FX disponíveis; não aceita URLs ou pacotes de terceiros.

php vendor/bin/fxartisan module:list
php vendor/bin/fxartisan module:install view --constraint=@dev --dry-run
php vendor/bin/fxartisan module:install view --constraint=@dev
php vendor/bin/fxartisan preset:install api --constraint=@dev --dry-run
php vendor/bin/fxartisan preset:install api --constraint=@dev

Em uma aplicação sem Console instalado, você também pode chamar o executável da cópia local do framework: php ../fxframework/bin/fxartisan preset:install minimal --constraint=@dev. O diretório atual determina o destino. O preset minimal não adiciona o Console ao projeto.

PresetRequisitos adicionadosUso
minimalfx-coreContainer, configuração e providers.
apifx-http e fx-consoleBase para respostas JSON, rotas e CLI; sem autenticação pronta.
wordpressfx-wordpressAdaptador e Core; WordPress deve existir no ambiente.
adminfx-admin e fx-consolePainel SQLite; exige configuração e admin:init.

O Composer resolve as dependências transitivas. Presets adicionam requisitos, sem remover pacotes não selecionados. Aplicar minimal em um projeto completo não o transforma em uma instalação enxuta. A restrição informada substitui a dos pacotes selecionados; revise o diff do manifesto e do lock.

Resultado: composer.json, composer.lock e vendor atualizados pelo Composer. Abra uma nova execução do Artisan para carregar os comandos recém-instalados. Esses comandos instalam pacotes; não criam o esqueleto de uma aplicação nem registram providers. No preset API, configure bootstrap e rotas conforme a ajuda HTTP. app:init gera uma base web com CSRF e não é um gerador específico de API.

Versões e simulação

Os pacotes FX ainda não foram publicados. Para os exemplos locais, configure repositories do tipo path apontando para ../fxframework/packages/*, minimum-stability: dev e prefer-stable: true no manifesto consumidor. Use --constraint=@dev. A restrição padrão ^1.0 é destinada a futuras releases; não significa que elas já estejam disponíveis.

--dry-run pede ao Composer uma simulação: não modifica o manifesto/lock nem instala vendor. Pode acessar os repositórios e o cache do Composer. A saída do Composer pode dizer “composer.json has been updated” durante a simulação; os arquivos permanecem preservados ao final.

Problemas comuns e próximos passos

  • Composer não encontrado: informe --composer=C:/composer/composer.phar, ajustando o caminho. Use aspas se houver espaços. No Unix, um executável Composer também é aceito. Wrappers .bat/.cmd não são aceitos; use o PHAR correspondente.
  • Pacote não encontrado: confira o repositório path no consumidor e a restrição @dev. Repositórios declarados apenas na dependência não são herdados.
  • Versões incompatíveis: consulte a saída do Composer e revise requisitos, lock e vendor. O comando retorna erro; não ignora requisitos de plataforma nem força atualização geral. Falhas de resolução normalmente restauram manifesto e lock; interrupções e falhas durante instalação não têm garantia de rollback completo.
  • Ambiente com COMPOSER ou COMPOSER_VENDOR_DIR: remova essas variáveis antes de usar os comandos, pois podem redirecionar os arquivos do projeto.
  • Scripts e plugins Composer ficam desabilitados nesta operação. Se seu projeto depende deles, execute os passos de configuração necessários separadamente, após revisão. Migrations e publicação de assets também são explícitas: instalar windows não executa fxwindows:install.
  • O preset admin instala fx-admin e fx-console; configure o projeto e execute admin:init. Com fx-modules instalado, use module:enable/disable/status/doctor/refresh para o ciclo de módulos. O pacote completo inclui o painel e passa a exigir PDO/SQLite.

Referência: comando require do Composer. Este manual funciona offline; o link externo é apenas complementar.

Ciclo de módulos

Instale fx-modules com module:install modules --constraint=@dev e execute o CLI novamente. module:status lista módulos registrados em config/modules.json; module:doctor valida o conjunto ativo; module:enable ID ativa suas dependências; module:disable ID bloqueia dependentes e preserva dados. module:refresh reconhece versões após atualização externa, sem baixar pacotes. Os comandos não aparecem no Console mínimo sem fx-modules.

Configure o provider no autoload e registre os módulos no bootstrap antes de boot(). Siga o manual distribuído em vendor/fxfavalessa/fx-modules/docs/index.html para o manifesto, os passos completos e a recuperação de erros. Estado: storage/framework/modules.json. Reinicie workers após alterações.

Inicializar o painel

Com fx-admin instalado, execute admin:init --email=seu-email@example.com. A senha é solicitada sem exibição; para automação use --password-env com o nome de uma variável contendo a senha. config/admin.php precisa definir database como caminho absoluto do SQLite fora de public. O comando cria o esquema e a primeira conta; não redefine contas existentes nem ativa fx-admin. Siga o manual distribuído no pacote Admin para configurar bootstrap, ativar o módulo e usar HTTPS. Nenhuma senha padrão é criada.

Fila de recuperação

Com Admin instalado, admin:mail --init cria a tabela da fila sem enviar, admin:mail --status mostra contagens e admin:mail --limit=20 processa mensagens reais. Requer config/admin.php com mail configurado, OpenSSL e symfony/mailer ^6.4 no consumidor para o transporte. O manual Admin explica variáveis, TLS implícito, tentativas e proteção da chave. O framework não agenda o processamento automaticamente.

Dicas e solução de problemas

fx-http habilita app:init, serve, route:list, make:request e make:middleware. fx-database habilita models e migrations. make:crud requer HTTP, Database e View. fx-windows habilita fxwindows:install. Execute na raiz da aplicação; migrações precisam de bootstrap/app.php inicializando a conexão. app:init sem banco gera uma aplicação web que não exige Database. module:install e preset:install já estão disponíveis; veja a seção de pacotes.

Classe não encontrada: confira o manifesto da aplicação e rode composer install. Repositórios Composer só são lidos do projeto consumidor; não basta declará-los em um pacote dependente.

O pacote completo fx-framework já contém todos os componentes e declara replace para impedir cópias concorrentes. Namespaces foram preservados; caminhos internos mudaram para packages. Utilize autoload, não require de caminhos antigos.

Compatibilidade dos comandos

Os nomes e descrições dos comandos nativos agora usam o atributo AsCommand, disponível no Symfony Console 6.4. Isso também evita comandos sem nome ao testar Console 7.4. Não mudam nomes, opções ou argumentos; basta atualizar os arquivos do pacote pelo Composer. Nenhuma migração de dados é necessária.

Para comandos próprios, prefira #[\Symfony\Component\Console\Attribute\AsCommand(name: 'minha:acao', description: 'Minha ação')] na classe ou passe o nome ao construtor de Command. As propriedades estáticas defaultName/defaultDescription não são reconhecidas pelo Console 7. Se Artisan apresentar “cannot have an empty name”, confira o registro do comando e o vendor próprio do consumidor.

Após instalar/atualizar examples/console, execute php examples/verify-package.php console na raiz para verificar isolamento. Resultado esperado: console: instalacao isolada OK. A suíte completa também confere os nomes e descrições dos nove comandos ajustados.

O pacote continua exigindo Symfony Console ^6.4 e PHP ^8.1. Uma suíte experimental passou com Console 7.4.18, Illuminate 13.30.1 e PHP 8.5.10 em cópia isolada; isso não amplia o contrato publicado nem certifica todos os pacotes nessa combinação. Não altere somente o requisito do Console sem revisar as dependências do consumidor.

Manual offline distribuído com o pacote. Atualize junto com cada mudança.

Transição para dependências modernas

O pacote aceita a linha Illuminate 10/Symfony 6.4 anterior e, nas dependências diretas que utiliza, Illuminate 13/Symfony 7.4. O requisito PHP ^8.1 da linha antiga permanece; Illuminate 13 exige PHP 8.3+. Novas resoluções em PHP recente podem escolher versões novas. Um lock existente não muda com composer install.

Em uma cópia de homologação, salve o lock antigo, configure composer config platform.php 8.3.0, atualize o pacote/dependências explicitamente e execute composer check-platform-reqs no runtime real. Confira composer show e rode os testes e o exemplo isolado deste pacote antes de trocar a instalação usada pela aplicação. platform.php apenas orienta a resolução.

As APIs herdadas do container, Request e Eloquent dependem da versão instalada; teste suas integrações. Core moderno inclui dependências adicionais de reflection/polyfills; HTTP moderno inclui clientes HTTP transitivos. Não atribua ganhos de velocidade sem medir. Configurações e banco do FX não são migrados automaticamente.

Se a versão continuar antiga, confira o lock e use composer why-not para diagnosticar restrições. Se surgir erro de PHP, use runtime compatível ou mantenha temporariamente a linha antiga. Em falha, restaure lock/arquivos consistentes na homologação. Illuminate 11/12 e Symfony 8 diretos não fazem parte desta ampliação. A ajuda central do repositório descreve comandos e evidências da etapa 8E.
