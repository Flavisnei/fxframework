InstalarUsarProvidersCompatibilidade

1. Instalar somente o necessário

Requisitos declarados: PHP ^8.1 e Composer 2. O Core requer illuminate/container, que traz illuminate/contracts, psr/container e psr/simple-cache. Não instala Eloquent, Smarty, HTTP, Console ou painel.

Em uma aplicação irmã de fxframework, crie composer.json:

{
  "name": "fx/minimo",
  "repositories": [{"type": "path", "url": "../fxframework/packages/core"}],
  "require": {"fxfavalessa/fx-core": "@dev"}
}

Execute composer install. A versão é de desenvolvimento local; ainda não foi publicada em um registro de pacotes. Use o caminho real do seu checkout.

2. Criar e configurar

<?php
require __DIR__ . '/vendor/autoload.php';
$app = new Fx\Framework\Foundation\CoreApplication(__DIR__);
$app->config()->set('app.name', 'Meu plugin');
echo $app->config()->get('app.name');

Resultado: Meu plugin. O Core não inicia sessão, não cria rotas e não substitui o container global Illuminate por padrão. Cada aplicação possui configuração própria.

get aceita um valor padrão como segundo argumento. Uma chave existente com null devolve null. Pontos separam níveis: mail.host representa o item host dentro de mail. set cria os níveis ausentes; ao atravessar um valor escalar, substitui esse valor por um array. all retorna o conjunto de configuração.

Configuração é explícita: não há leitura automática de .env ou de diretórios. Para carregar um arquivo PHP de sua aplicação, passe seu array ao construtor de Repository e registre a instância no container.

3. Registrar serviços

use Fx\Framework\Support\ServiceProvider;

final class MeuProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->bind('mensagem', fn () => 'Pronto');
    }
}
$app->registerProviders([MeuProvider::class])->boot();
echo $app->make('mensagem');

Resultado: Pronto. bind resolve serviços; singleton compartilha uma instância dentro do container. O método boot opcional do provider aceita injeção de dependências. Registre os providers antes de chamar boot; registros posteriores ao boot concluído são inicializados imediatamente. Evite registro recursivo de providers durante a inicialização.

4. Compatibilidade e diagnóstico

O pacote completo mantém Fx\Framework\Foundation\Application com os serviços web e contém o mesmo código do Core via autoload. Não é necessário instalar ambos. Namespaces de Container e ServiceProvider foram preservados, mas seus arquivos estão agora neste pacote: use o autoload do Composer, não require para caminhos internos antigos.

ServiceProvider agora recebe CoreApplication. Providers portáveis devem depender apenas de seus recursos. Providers que chamam withDebug, setRequest ou usam rotas continuam específicos da Application completa. Se um provider redeclara a propriedade protegida $app com o tipo Application, remova a redeclaração ou ajuste para CoreApplication.

O construtor de Container usado diretamente preserva o registro global legado; para integração isolada, use CoreApplication ou Container(false). Isso não isola versões conflitantes de bibliotecas entre plugins WordPress: o adaptador e essa validação ainda estão pendentes.

Se uma classe não for encontrada, confira vendor/autoload.php da aplicação e rode composer dump-autoload após atualizar o pacote. O Core não oferece fxartisan, templates nem autenticação. A divisão independente dos demais componentes será feita na etapa seguinte.
